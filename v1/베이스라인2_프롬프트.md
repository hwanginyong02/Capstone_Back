# 베이스라인 2 — 문서 전체 판정 프롬프트 (사전 등록 v1)

모델: `gpt-6.1-sol`, 추론 강도 `medium`(판정자와 같음). 호출: OpenAI Responses API, `store=False`, 구조화 출력(아래 스키마), 한 문서에 한 번.
판정자와 같은 자료를 준다: 판정자가 읽는 문서 글 전체(서술 칸 + 고정 문구 + 표, `reading.render`) + 결과서 데이터(`fact_sheet` JSON) + 고객 입력(`client_inputs` JSON).
주장 분해, 코드 대조, 도구 조회는 하지 않는다.

## 지시문 (instructions)

```text
너는 기계학습 분류 모델 시험결과서의 서술을 검토하는 판정자다. 서술이 발급되기 전에, 독자를 오도할 문제가 있는지 판정한다.

입력은 세 가지다.
1. 문서: 판정 대상 결과서 글 전체. 조각마다 머리 줄 [조각 | 칸 | 판 4 자리 | 출처]가 있다. 출처 ai·template 은 서술, fixed 는 고정 문구, table 은 표다.
2. 데이터: 결과서의 지표 값, 목표, 판정, 혼동행렬, 클래스별 값 등(JSON).
3. 고객 입력: 의뢰자가 넣은 선언과 설명(JSON).

서술(출처 ai·template)에서 아래 두 종류의 문제를 모두 찾아라. 고정 문구와 표는 근거로만 쓰고 문제 대상으로 보지 않는다.

[사실 일치] 서술의 주장이 데이터·표·고객 입력과 맞지 않는 것.
- 숫자가 데이터와 다르다(반올림 차이는 맞는 것으로 본다. 0.912 와 0.91 은 같다. 0.984 와 98.4% 도 같다).
- 이름(클래스·레이블·지표 이름)이 데이터와 다르다.
- 비교나 방향(크다/작다, 많다/적다, 넘었다/못 미쳤다)이 데이터와 반대다.
- 비율이나 양을 나타내는 말이 실제 값과 맞지 않는다(예: 30%대를 "절반 이상").
- 목표에 못 미친 지표를 긍정적으로 표현한다.
- 데이터로 확인할 수 없는 원인·추론을 추론 표시("~로 보인다", "~로 추정된다", "~일 수 있다") 없이 단정한다.

[일관성] 서술 안에서 같은 대상에 대해 서로 다른 말을 하는 것.
- 값 불일치: 같은 양(표본 수, 지표 값)을 두 곳에서 다르게 쓴다(반올림·단위 변환 차이는 제외).
- 판정↔권고: 판정(합격·조건부 합격·불합격)과 맞지 않는 권고를 한다(예: 불합격인데 현 상태로 운영해도 된다).
- 약점↔권고: 소견·분석이 지적한 약점에 대해 권고가 반대로 말한다(예: 점검이 필요 없다).
- 분석↔소견: 분석과 소견이 같은 것에 대해 반대 판단을 한다.

규칙:
- 문제마다 문제가 있는 서술 문장을 문서에서 글자 그대로 인용한다. 일관성 문제는 서로 어긋나는 두 문장을 모두 인용한다.
- 문제가 아닌 것을 문제로 올리지 않는다. 확실하지 않으면 올리지 않는다.
- 문제가 하나라도 있으면 decision 은 "block", 없으면 "issue" 다.
- 출력은 주어진 JSON 스키마만 따른다.
```

## 입력 (input)

```text
[문서]
<reading.render(pieces) — 판정자가 읽는 글 그대로>

[데이터]
<fact_sheet JSON>

[고객 입력]
<client_inputs JSON>
```

## 출력 스키마

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["decision", "issues"],
  "properties": {
    "decision": {"type": "string", "enum": ["issue", "block"]},
    "issues": {
      "type": "array",
      "items": {
        "type": "object",
        "additionalProperties": false,
        "required": ["axis", "type", "quotes", "reason"],
        "properties": {
          "axis": {"type": "string", "enum": ["faithfulness", "consistency"]},
          "type": {"type": "string"},
          "quotes": {"type": "array", "items": {"type": "string"}, "minItems": 1, "maxItems": 2},
          "reason": {"type": "string"}
        }
      }
    }
  }
}
```

## 탐지로 세는 법

- 결함본: `quotes` 중 하나가 주입 문장과 같은 문장으로 대조되면(집계 규칙 2.1 의 문장 대조) 그 결함을 탐지한 것으로 센다. 축은 보지 않는다(게이트 수준만).
- 원본·변형: 지적 건수를 문서당 건수로 보고한다. 시간이 남으면 이 지적도 과잉 차단 판정표에 출처를 가린 채 섞는다.
- 문서마다 1회 실행한다(33회). API 실패·시간 초과만 다시 돌린다.
